# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

GestiMed: a desktop app shown to users as **MedManager** (`Theme.NOM_LOGICIEL`: window titles, banner, login; the jar, packages, log folder `~/GestiMed` and the `gestimed` DB account keep the old name) for running a medical practice (patients, consultations, prescriptions/ordonnances, lab analyses, appointments). It uses Java Swing with MySQL and is built with Maven. The project was migrated from NetBeans/Ant with hard-coded `.jar` paths. Code, comments, identifiers and user-facing messages are in **French**, so keep new code consistent with that.

## Commands

```
mvn test                                   # compile + run all tests (headless, no MySQL needed)
mvn test -Dtest=PatientServiceTest         # single test class
mvn test -Dtest=PatientServiceTest#methode # single test method
mvn package                                # target/gestimed-3.5-jar-with-dependencies.jar (runnable)
mvn exec:java                              # run the app (main: My_application.PrincipalForm)
mvn verify                                 # tests + JaCoCo coverage check + SpotBugs (what CI runs)
```

- Target is Java 8 (`maven.compiler.release=8`), so don't use newer language/API features (no `var`, `List.of`, records, etc.). Any recent JDK can compile it.
- DB settings come from `src/main/resources/My_application/Files_Res/db.proprieties` (the misspelling is intentional and referenced in code). That file has no password and must never contain one. Values are overridden, in increasing order of priority, by a local `gestimed.properties` (path from `-Dgestimed.config`, otherwise the working directory, otherwise `user.home`; it is git-ignored), then by `-Dgestimed.db.url|user|password|driver=...`. `-Dgestimed.utilisateur` / `-Dgestimed.medecin` pick the user offered at first use and the default doctor (default 1).
- The default DB account is `gestimed` (not `root`), created by `sql/creer_compte_gestimed.sql` with SELECT/INSERT/UPDATE/DELETE only. The connection uses `sslMode=PREFERRED`. `Database` logs a warning if it connects as `root`.
- Error messages shown to the user never include SQL or stack traces: `ControleurBase` displays a generic message and the detail goes to the log file set up by `Journal.installer()` (`~/GestiMed/gestimed0.log`, folder overridable with `-Dgestimed.journal`). A duplicate key (MySQL 1062) surfaces as `DoublonException`, which services translate into a `MetierException`.
- **Roles** (V10): `utilisateur.role` = `SECRETAIRE` | `MEDECIN` | `ADMIN` (`entities/Role`, default `MEDECIN`). `Session` implements `service/ControleAcces` (`exiger(Role...)`); services check roles themselves (`ControleAcces.AUCUN` in tests, and no check while no session is open, e.g. command-line tools). `DossierService` (dossier, consultations, consultations of the day) is `MEDECIN` only; `MembresService` is `ADMIN` only: members list, `creerCompte` (login + provisional password, `utilisateur.doitChanger`; for a new doctor the `medecin` fiche is created in the same transaction), `modifier`, `motDePasseProvisoire`, `definirActif`, doctor fiches (`modifierMedecin`, `definirMedecinActif`, refused while the doctor has future PREVU appointments or an active account). The last active admin is protected. A deactivated doctor (`medecin.actif`) disappears from `RendezVousService.medecins()` (agenda, booking); `tousLesMedecins()` keeps the inactive ones for naming past data. A provisional password must be replaced at login (`AuthentificationService.connecter` returns the user without opening the session, then `remplacerMotDePasseProvisoire`); every member can use the side menu entry « Mot de passe » (`changerMonMotDePasse`; the main window has no menu bar any more). Small hand-written dialogs use `vue/Formulaire`. **Statistics** (admin, page `admin/PageStatistiques` next to Membres): `StatistiquesService.calculer(debut, fin, idMedecin)` returns aggregate counts only (no patient names) from `StatistiquesDao` (SQL GROUP BY on consultation, rendezvous, salle_attente; « nouveaux patients » = first consultation ever falls in the period), `serie` groups by day/week/month for `admin/GraphiqueBarres`; exports: PDF (`RapportService.statistiques`) and CSV for Excel (`;`, UTF-8 with BOM). `PrincipalForm` picks its page by role: the secretary gets no consultations panel, the admin lands on `admin/PageMembres`. A doctor also has the side menu entry « Consultations »: `consultations/PageConsultations` (CardLayout next to the home page, controller `ConsultationsController`) lists the consultations of a chosen date (◀ date ▶, « Aujourd'hui », `DossierService.consultationsDuJour`), double-click opens the patient's file. Deployment: the secretary's PC hosts MariaDB and carries the `secretaire` and `admin` accounts; doctors' PCs connect over the LAN (`docs/installation-reseau.md`, `sql/ouvrir_reseau_local.sql`, check a post with `My_application.outils.InstallationPoste`).
- **Patient registration**: `Patient/FichePatient` (hand-written dialog, no `.form`, controller `FichePatientController`) creates and edits a patient file; it replaced `NewPatient`. `PatientService.creer` requires a phone number, normalises phones (`normaliserTelephone`: `+213`/`00213` → `0`, Algerian mobile or landline format) and e-mails, and `doublonsPossibles` (same name and birth date, or same phone) lets the user pick the existing file instead of creating a duplicate. `rechercher` searches by phone when the text is digits. `modifier` is audited as `MODIFICATION_PATIENT`. V11 normalised existing phones and indexed `telPatient` and the birth date. **File number** (V15): `patient.numeroDossier` (VARCHAR(20), unique, case-insensitive, digits/letters/`/ - .`, stored upper-case by `normaliserNumeroDossier`) is the number the practice knows; `idPatient` stays the technical auto-increment key and is never typed in any more. Existing files kept their number (`numeroDossier = idPatient`). Left empty at registration, it gets `prochainNumeroDossier()` (largest all-digit number + 1), retried if another post takes it at the same time; it can be changed in the file (uniqueness checked). `rechercher` puts the file whose number is exactly the text first. In `ListePatient`, a double-click opens the file for a secretary and the medical record for a doctor; "Prendre un rendez-vous" opens the appointments screen for the selected patient.
- **Login and audit**: `PrincipalForm.main` shows `ConnexionForm` first. `AuthentificationService` checks PBKDF2 hashes (`service/MotDePasse`, stored in `utilisateur.motDePasse`), locks a login for 30 s after 5 failures and opens `Session`. While no user has credentials, the login screen creates the first account instead. Further accounts: `My_application.outils.GestionComptes` (command line: `ajouter <role> <login> <nom> <prenom> [idMedecin]`, `role`, `definir`, `activer`/`desactiver`, `liste`, `journal`). `JournalAcces` writes to `journal_acces` (who opened or modified which patient file). Services take it as an optional constructor argument (`JournalAcces.AUCUN` in tests that don't care). Writes go in the same transaction as the action, and a failed audit write makes the action fail.
- **MySQL integration test** (`MySqlIntegrationTest`) is skipped unless you pass `-Dgestimed.test.db.url=jdbc:mysql://localhost:3306/<name>_test -Dgestimed.test.db.user=... -Dgestimed.test.db.password=...`. The DB name must end in `_test` because before each test it runs Flyway `clean` (drops every table) then all migrations.
- **Schema = Flyway migrations** in `src/main/resources/db/migration/` (`V1__schema_initial.sql`, reconstructed from the code's queries, then `V2__authentification.sql`, …). Never edit an applied migration; add `V<n>__description.sql`. `dao/jdbc/Migrations` wraps Flyway 9 (last line supporting Java 8; `flyway-mysql` needed for MySQL/MariaDB). Migrations are applied with an admin account by `My_application.outils.MigrationBase migrer [compte]` (creates the DB if missing; adopts a pre-Flyway DB as version 1 or 2 depending on whether `journal_acces` exists). The app account `gestimed` cannot alter tables, so at startup `PrincipalForm` only calls `Migrations.etat()` and refuses to start if a tracked DB has pending migrations. Fresh install: `MigrationBase migrer`, then `sql/creer_compte_gestimed.sql`, then `sql/donnees_initiales.sql`. Tables must be InnoDB or transactions silently do nothing. From V3 on, migrations use MariaDB syntax (`DROP CONSTRAINT IF EXISTS`), so MariaDB 10.2+ is required (the practice runs XAMPP MariaDB 10.4, which lacks `RENAME COLUMN`/`RENAME INDEX`: use `CHANGE` and drop/re-add). Unmeasured vital signs are NULL in `consultation` (V4); `JdbcConsultationDao` maps NULL <-> `consultation.NON_RENSEIGNE`. Blood pressure (V16) is two SMALLINT columns in mmHg, `pressionSystolique`/`pressionDiastolique` (both NULL or both set, CHECK 40-300 / 20-200, systolic > diastolic); `ConstantesVitales.pression` accepts 12/8 or 13,5/8 (each value ≤ 30 is cmHg, ×10) or 120/80 and returns mmHg, `consultation.getPressionA()` formats "120/80". V16 converted the old text column the same way and copied the implausible entries to `consultation_pression_ancienne` instead of losing them. `rendezvous.prisLe` (V8, one DATETIME) is split into `Rendez_Vous.dateFix`/`heureFix` by `JdbcRendezVousDao`. Each appointment belongs to a doctor (`rendezvous.idMedecin`, NOT NULL since V9). Appointments are never deleted: cancelling or marking absent sets `etat` (`Rendez_Vous.ETAT_ANNULE`/`ETAT_ABSENT`), which frees the slot because the unique key (V12) is (idMedecin, date, heure, occupe), `occupe` being a generated column that is NULL for those states. `RendezVousService` books with the doctor chosen in the agenda, else `Session.getIdMedecinDuPoste()` (null for a secretary or admin, who must choose unless the practice has a single doctor), counts slot capacity per doctor among occupying appointments only, and also moves (`proposerDeplacement`/`deplacer`), cancels, marks absent, searches a patient's appointments and lists a day (`RapportService.listeRendezVous` PDF). State changes are conditional updates (`changerEtat(id, etatAttendu, nouvel)`) so a stale screen on another post gets a message instead of overwriting. The agenda colours come from `etat` (`StatutRendezVous`). **Waiting room** (V13): `salle_attente` holds one row (`entities/Passage`) per patient who arrived, with or without an appointment (`etat` 0 waiting, 1 in consultation, 2 done, 3 left); a generated column `present` in a unique key keeps a patient only once at a time, and an appointment gives at most one passage. `SalleAttenteService` handles arrival (the appointment goes to ARRIVE), walk-ins, urgency, "left without consultation" (appointment ABSENT), end of day (past PREVU appointments marked absent, then `Bilan`) and, for doctors only, calling the next patient; `DossierService.enregistrer(dossier, frais)` ends the patient's passage and appointment in the same transaction (`SalleAttenteService.cloreConsultation`). **Fees and leaving** (V17): the passage then goes to `Passage.A_REGLER` (4, still `present`, out of the doctor's `file()`) with `salle_attente.frais` (whole dinars, NULL = not given); `DossierPatientForm` asks the doctor for the fees when closing a file whose patient is in a queue (`fraisADemander`, pre-filled with `dernierFrais`). The secretary's home (`presents()`, `brancherSalleAttente(..., avecCaisse)`) lists those patients first and is told by a banner; « Encaisser et libérer… » calls `liberer(passage, montantRegle)` → `TERMINE`, `sortieLe`, `montantRegle`/`regleLe`. `SalleAttenteService.montant` parses typed amounts; the day's `Bilan` gives `aRegler` and `encaisse`. Posts see each other's changes through the `evenement` table: every change publishes a row, and `PrincipalForm` runs a 3 s `javax.swing.Timer` that calls `AccueilController.verifierEvenements()`, which reads only the last id (silently, errors go to the log) and reloads the home page when it changed; the secretary is told when a doctor calls a patient. Events older than 7 days are purged at startup. Back up with `mysqldump`, not phpMyAdmin's export, which drops CHECK constraints, engine and charset of tables that have a CHECK.
- The runnable jar is built with `src/assembly/jar-executable.xml`, which merges `META-INF/services` (otherwise Flyway loses its MySQL plugin).
- **Quality gates** (`mvn verify`, run by `.github/workflows/ci.yml` with a MariaDB 10.4 service): JaCoCo requires ≥ `couverture.minimum` line coverage in each of `service`, `dao.jdbc` and `controller`; SpotBugs (threshold Medium) fails the build on any finding not excluded with a reason in `spotbugs-exclusions.xml`.

## Architecture

Layering, top to bottom (all under `src/main/java/My_application/`):

1. **Swing views**: NetBeans GUI-builder forms (`*.java` + matching `*.form`) in the root package and feature packages (`Patient/`, `Ordonnance/`, `Analyse/`, `rendezvous/`, `salle/`, `messagerie/`, …). Code inside `// <editor-fold>` / `initComponents()` regions is generated from the `.form` XML. Keep the `.form` file in sync if you change those regions. Custom `TableModel`/renderer classes are in `modelTableau/`, `TableModelPrincipale/` and the feature packages ("Rondu" = renderer). Shared UI helpers are in `vue/`.
2. **Controllers** (`controller/`): each window implements a `Vue` sub-interface (e.g. `AccueilVue`) and gets its controller in its constructor. Controllers extend `ControleurBase`, whose `tenter(Runnable)` / `tenter(Supplier<T>, T siEchec)` (use lambdas) show `MetierException` messages as-is and logs `DataAccessException`/other runtime errors before showing a generic message. Route UI actions through `tenter` rather than catching exceptions in views.
3. **Services** (`service/`): business rules. They throw `MetierException` for validation failures. `Session` holds the current user/doctor. `report/RapportService` builds ordonnance and analysis-request PDFs with OpenPDF (`com.lowagie.*`), which replaced JasperReports. Every PDF is shown in the in-app preview `report/ApercuPdf` (PDFBox 3: pages rendered at the current zoom, « Imprimer » through Java's print dialog, « Enregistrer sous… », « Visionneuse »), via `AfficheurApercu`, which falls back to `AfficheurSysteme` (system viewer) when the preview cannot open or without a screen; `imprimer` opens the preview then the print dialog.
4. **DAO** (`dao/`): one interface per aggregate, plus the `DAOFactory` abstract factory. `DAOFactory.enTransaction(UniteDeTravail)` runs work atomically. For example, saving a consultation writes to ~6 tables in a single transaction (`DossierService`).
5. **JDBC implementation** (`dao/jdbc/`): `JdbcDAOFactory`, `Jdbc*Dao`, `JdbcHelper` (prepared-statement helpers, `insertAndGetKey`, `queryParCle` to group rows by consultation id), `RowMapper`/`Mappers`, and `TransactionManager`, which supports nesting (only the outermost call commits or rolls back, tracked per thread). During a transaction the connection is pinned in a `ThreadLocal`: if it drops mid-transaction the next statement fails instead of silently reopening a fresh autocommit connection. One `ReentrantLock` (owned by `TransactionManager`, shared with `JdbcHelper`) serializes all DB access, so a background read waits for a running transaction. `Database` is a single shared connection that reopens itself when it goes stale; it only calls `isValid` after 30 s idle. It never shows dialogs; errors propagate as `DataAccessException`. Load aggregates per patient, not per consultation (`DossierService.ouvrirDossier` uses 6 queries whatever the number of consultations).

**Composition root:** `AppContext` is the only place that picks concrete implementations. There is no global instance: `PrincipalForm.main` creates it once with `AppContext.mysql()` (command-line tools do the same, tests use `new AppContext(daoFactory)`) and it is passed by constructor. Windows that open other windows (`PrincipalForm`, `ListePatient`, `DossierPatientForm`) receive the `AppContext`; the others receive only the services they need (e.g. `OrdonnanceForm(consultation, CatalogueService)`). UI or service code must not open JDBC connections directly.

**Look and feel:** FlatLaf with a teal "medical" palette. `vue/Theme.installer()` (called from `PrincipalForm.main`) loads `src/main/resources/My_application/theme/FlatLightLaf.properties`. Every window calls `Theme.harmoniser(this)` right after `initComponents()`. That call rewrites at runtime the fonts, colours, borders and PNG icons hard-coded by the NetBeans GUI builder, so generated code and `.form` files don't need hand-editing for styling. New windows must make the same call. `harmoniser` also turns every `TitledBorder` group into a white rounded "card" (`vue/BordureCarte`, title inside, panels inside the card get the card's white). Page chrome follows the appointments screen (`rendezvous/calandar`): `EnTetePage.installer(window, icon, title, subtitle)` (called right after `harmoniser`) puts the common page header above any window, and the main window has a `Bandeau` (name on the left, live clock and date centred, user on the right) and a `MenuLateral`. In hand-written code (renderers, dialogs), use the palette constants and `Theme.police()` / `Theme.cellule(...)` instead of literal colours and fonts. For interface icons, use `Icones.svg(name, size, colour)` with the Tabler SVGs in `res/svg/`. Legacy PNG → SVG mappings live in `Icones`. Patient avatars are colour SVGs in the same palette (`res/svg/patients/`: homme, femme, garcon, fille, bebe-garcon, bebe-fille), picked by `Icones.patient(p, taille)` from sex and age and not tinted.

`entities/` holds plain domain objects with legacy lowercase class names (`patient`, `consultation`, `medecin`, `Rendez_Vous`, …). Keep those names as they are. Their fields are private and dates/times are `java.time` (`LocalDate`, `LocalTime`): `java.sql.Date`/`Time` only appear in `dao/jdbc` (`Mappers.jour/heure` when reading, `JdbcHelper` converts `java.time` parameters when binding). Format dates with `DateTimeFormatter` and `Locale.FRENCH`, not `SimpleDateFormat`.

## Tests

JUnit 4, under `src/test/java`. Most tests don't need a database:
- `fake/MemoireDAOFactory`: an in-memory implementation of the whole DAO layer, used for service and controller tests.
- `fake/FauxJdbc`: a fake JDBC driver built on dynamic proxies. It records the SQL and bound parameters, returns scripted rows, simulates generated keys and checks that statements and result sets get closed. Use it to test `Jdbc*Dao` classes.
- `fake/FausseVue`: records the messages a controller shows. `fake/Donnees` provides sample entities.

## Notes

- Legacy or prototype classes (`AddPatient`, `AjouterPat*`, `Password`, `ImagerieForms/Imagerie`, `ServiceReseau`, `my_model`, `SalleAtten*`) were never called. They are kept in `archives/prototypes/` (see its `LISEZMOI.md`), outside the build and the jar. Don't add them back to `src/` without a reason. `Imagerie` would then need the NetBeans `AbsoluteLayout` dependency again.
- **Messaging** (V14) replaced the old TCP chat (`Chat/`, port 7777, removed): messages only go through the database. `message_interne` (`entities/MessageInterne`; `idDestinataire` NULL = "Tout le cabinet", `idExpediteur` NULL = system message, optional cited patient), `message_lu` (read receipts, deleted with the message) and `utilisateur_presence` (server time, so posts' clocks don't matter). `MessagerieService` is for SECRETAIRE and MEDECIN accounts (admins are not listed), purges messages older than 12 months at startup. `messagerie/FenetreMessagerie` is created hidden by `PrincipalForm` (not for the admin); the same 3 s timer calls its `verifier()` (reads only the last message id, then the threads if it changed), which updates the unread badge on the `MenuLateral` entry (`setBadge`) and plays `Sons`; presence is signalled every 30 s and removed when the app closes. Message text is HTML-escaped before display.
- Most database calls still run synchronously on the Swing EDT. Slow reads go through `ControleurBase.enArrierePlan(Lecture, Affichage)`: the read runs in a `SwingWorker` (`Executeur.SWING`), the display and error reporting happen on the EDT. Controllers take an optional `Executeur`; tests pass `Executeur.IMMEDIAT`. `AccueilController` and `MessagerieController` use it, and `enArrierePlanSilencieux` for periodic checks that must not pop up dialogs.
- `vue/AutoCompletion` listens to document changes (not key codes) and debounces lookups with a 250 ms `javax.swing.Timer`.
